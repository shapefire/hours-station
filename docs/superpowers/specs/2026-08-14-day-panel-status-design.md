# 工作日历日明细：休息 / 请假 / 支援 / 试工 — 设计说明

日期：2026-08-14  
状态：已确认（界面原型 + 数据/统计口径）  
范围：工作日历右侧日明细扩展；统计口径同步调整  
原型：`.superpowers/brainstorm/.../interactive-prototype-a.html`（方案 A 可交互稿）

---

## 1. 背景

当前日明细只支持「到岗排班」（姓名 + 时段 + 备注）。管理者还需要登记：

1. **休息人员**（可多选）
2. **请假人员**（可多选）
3. **支援人员**（两类语义）
   - **外援**：其它店铺人员来本店支持 → 按正常到岗安排，带「外援」标识，**工时计入本店**
   - **支援**：本店员工外派其它店铺 → 需排时段，与到岗分区展示，**工时不计入本店**
4. **试工人员**：在到岗安排上标识「试工」（可与外援同时标记）

## 2. 目标

- 右侧日明细采用 **分段列表（方案 A）**：到岗主列表 + 休息 / 请假 / 支援分区
- 同日同人 **四种状态互斥**：到岗 / 休息 / 请假 / 支援
- 本店合计工时仅含到岗（含外援、试工）；支援单独统计列
- 明确登记的休息、请假计入月度「休息天数」；未登记日仍算休息

## 3. 非目标

- 多店铺主数据、跨店双向同步排班
- 休息 / 请假填写时段（本版整日、无时段）
- 支援必填目标店铺（备注可选填写）
- 登录 / 权限 / 审批流
- 月历格内展示支援角标（本版可不做；格内人数/工时只统计到岗）

## 4. 界面结构（方案 A）

### 4.1 布局

延续左月历 + 右日明细。右侧自上而下：

1. **标题行**：日期 · 到岗人数 · **本店合计工时**（仅到岗）
2. **摘要行**：休息 N · 请假 N · 支援 N（支援工时不进上方合计）
3. **操作**：预览｜复制到…｜清空当日｜**新增到岗**
4. **到岗安排**：现有列表；行上可显示徽章「外援」「试工」
5. **休息人员**：chip 多选，整日无时段
6. **请假人员**：chip 多选，整日无时段
7. **支援（本店外派）**：独立列表，虚线/弱化样式；姓名 + 时段 +「支援」徽章；注明不计入本店工时

### 4.2 到岗表单增量

在现有姓名 / 时段 / 备注上增加：

- 勾选 **外援**（默认不勾）— 可自由输入姓名；来源店铺可写备注
- 勾选 **试工**（默认不勾）— 可与外援同时勾选

### 4.3 交互规则

- 休息 / 请假：从花名册多选；已被其它状态占用的人禁用并提示原因
- 支援：选择本店花名册中未被占用的人 + 开始/结束时间（算法与到岗相同，仅统计口径不同）
- 删除 chip / 行即时生效；清空当日清除四类记录
- 冲突：同日同人已有任一状态时，禁止再登记其它状态，明确提示

### 4.4 预览与复制

- **预览文本**：按分区输出。到岗行保留现格式，姓名后可附带 `[外援]` / `[试工]`；休息 / 请假列出姓名；支援单独一节并标注不计入本店
- **整日复制 / 单人复制**：复制完整状态与标识（含 rest/leave/support 与外援/试工）；粘贴日若同人冲突则跳过并提示（沿用现有跳过语义）
- **顶部合计 / 月历格**：只汇总 `on_duty` 的有效工时与人数

## 5. 数据模型

在现有 `work_entries` 上扩展（不新建第二套人员表），保持 `work_date + employee_id` 唯一 → **天然互斥**。

| 列 | 类型 | 说明 |
|----|------|------|
| `status` | String | `on_duty` \| `rest` \| `leave` \| `support`；默认 `on_duty` |
| `is_external` | Boolean | 是否外援；仅 `on_duty` 有意义；默认 false |
| `is_trial` | Boolean | 是否试工；仅 `on_duty` 有意义；默认 false |
| `start_time` | Time \| null | `on_duty`、`support` 必填；`rest`、`leave` 为 null |
| `end_time` | Time \| null | 同上 |

校验：

- `status ∈ {on_duty, rest, leave, support}`
- `on_duty` / `support`：`end_time > start_time`；按现有规则算展示用有效工时
- `rest` / `leave`：禁止带时段；`is_external` / `is_trial` 必须为 false
- `support`：`is_external` / `is_trial` 必须为 false
- 外援自由输入姓名：不在花名册则自动加入（与现状一致），靠 `is_external` 区分

迁移：既有行 `status=on_duty`，`is_external=false`，`is_trial=false`，时段不变。

## 6. 统计口径

| 类型 | 出勤 | 本店总工时 | 休息天数 | 支援列 |
|------|------|------------|----------|--------|
| 到岗（含外援、试工） | ✓ | ✓ | — | — |
| 休息、请假 | — | — | ✓ | — |
| 支援 | — | ✗ | — | ✓（单独） |
| 未登记自然日 | — | — | ✓ | — |

补充：

- **出勤天数**：该日存在 `on_duty` 记 1（按人按日）
- **支援天数**：该日存在 `support` 记 1（按人按日）；支援时长按规则计算仅作展示，**不计入**本店总工时、出勤
- **休息天数**：`当月天数 − 出勤天数 − 支援天数`  
  （等价于：明确 `rest` + `leave` + 未登记日；**支援日不计入休息天数**）
- 仅统计当月至少有一条任意 `work_entries` 的员工（含仅休息/请假/支援），与「登记人数」语义对齐
- 例：整月只有 rest/leave → 出勤 0、支援 0、休息天数 = 当月天数；若有 2 天支援、其余未登记 → 支援 2、休息 = 当月天数 − 2

## 7. API

延续 `/api/entries`，请求/响应增加字段：

| 字段 | 说明 |
|------|------|
| `status` | 见上 |
| `is_external` | bool |
| `is_trial` | bool |
| `start_time` / `end_time` | rest/leave 可省略或 null |
| `effective_hours` | 服务端计算；`rest`/`leave` 为 0；`support` 返回展示用时长，日历合计接口排除 |

调整点：

- `GET /api/entries?date=`：返回当日全部状态；前端按分区渲染
- `POST` / `PATCH`：按 status 校验时段与标识
- `GET /api/calendar`：日格 `count` / `total_hours` **仅 on_duty**
- `GET /api/stats/monthly` 及按人逐日：按第 6 节口径；按人增加支援天数/支援工时字段；逐日 `status` 区分 work / rest / leave / support（无记录仍为 rest）

## 8. 错误处理

- 同日同人冲突：400，文案含已占用状态（如「张三当日已在休息」）
- 非法组合（请假带时段、支援标试工等）：400，明确字段错误
- 清空当日：删除该日全部 status 的条目

## 9. 测试要点

- 互斥：到岗后不可再标休息/请假/支援，反之亦然
- 外援/试工徽章与默认不勾；两者可同时为 true
- 本店合计与月历格不含支援工时；支援时长仍可在支援区展示
- 休息/请假无时段；统计休息天数含明确 rest/leave 与未登记日
- 预览文本含分区与标识
- 复制粘贴保留 status 与标识，冲突跳过
