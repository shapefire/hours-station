# 员工月度工时核审与异议审核

日期：2026-08-31  
状态：已确认（brainstorming）  
范围：员工按姓名进入近月核审、按天提异议（主时段+加班）、整月确认锁定；管理员逐条确认/无效，确认后更新当天排班  
相关代码（拟新增/改动）：`backend/app/models.py`、新 `reviews` 服务/路由、`frontend` 新页面与顶栏导航

---

## 1. 背景

月底需要每位员工自行核对当月每天上班时段是否正确。有误则可对单日提出异议（附建议时段与可选备注），由管理员逐条确认或判无效；确认后更新该员工当天排班。现有系统无登录，统计看板面向管理者只读，改时段走日历 `PATCH /api/entries`，无异议/核审流程。

## 2. 目标

1. 员工输入花名册姓名，查看默认「最近一个自然月」的逐日安排，可切到当前月。
2. 任意一天可提异议：建议主时段 + 加班时段（可新增、可清空）+ 可选备注。
3. 底部「确认本月核审」：提交已填异议 + 标记本月已核审并锁定，之后不可再改。
4. 管理员在独立审核页对**每一条异议（一人一天）**单独「确认」或「无效」。
5. 确认仅落库该日：写成到岗并应用建议时段；无效不改排班。
6. 现有顶栏可直接跳转员工核审页与管理员审核页。

## 3. 非目标

- 不引入登录、角色、口令或权限校验（姓名即可进入，与现状一致）。
- 不在本功能中改状态为休息/请假/支援（确认落库一律为到岗）。
- 不批量「一键通过」某人全部异议（必须按天逐条处理）。
- 不强制通知/推送员工审核结果（员工再进核审页可读状态即可）。
- 不改统计看板口径与 Excel 导出逻辑（仅新增入口与新表）。

## 4. 已确认决策

| 项 | 选择 |
|----|------|
| 身份 | 仅输入花名册姓名 |
| 可异议字段 | 主时段 + 加班（可新增、可双空清除）+ 可选备注 |
| 可异议日期 | 当月每一天（含未安排） |
| 底部确认 | 整月核审完成声明 + 一并提交已填异议；记录已核审 |
| 默认月份 | 见 §5.3；可切到当前自然月 |
| 提交后 | 本月锁定，不可再改 |
| 确认落库 | 一律写成到岗；有原记录则更新，无则新建 |
| 管理审核粒度 | 按单条异议（某一天），确认/无效互不影响其他天 |
| 实现形态 | 方案 1：独立 `/review` + `/review/admin` |

## 5. 用户流程

### 5.1 员工 `/review`

1. 输入姓名 → 匹配花名册（不存在则报错）。
2. 展示目标年月明细：日期、原状态、原主时段、原加班。
3. 对有问题的天展开「提出异议」：填写建议开始/结束、加班开始/结束、备注（可选）。
4. 点「确认本月核审」（需二次确认）：  
   - 写入 `monthly_reviews`；  
   - 将本页已填异议写成 `time_disputes`（`pending`）；  
   - 未填异议的天视为认可，不写争议记录。
5. 之后再进入该月：只读；可看已提交异议及 `pending` / `confirmed` / `rejected`。

### 5.2 管理员 `/review/admin`

1. 默认列表：`pending` 异议。
2. 每条展示：姓名、日期、原状态/时段 vs 建议时段（含加班）、备注。
3. **确认**：校验建议时段 → 更新或新建该日 `WorkEntry` 为 `on_duty` → 异议标 `confirmed`。
4. **无效**：异议标 `rejected`，不改 `WorkEntry`。
5. 顶栏「异议审核」可从日历/统计直接进入本页。

### 5.3 默认月份算法

令今天为 `today`：

- 若 `today.day == 1`（月初第一天）：默认 **上一个自然月**（例如 9/1 → 8 月）。
- 否则：默认 **当前自然月**（例如 8/15、8/31 → 8 月）。

员工可用年月控件切换到**当前自然月**（当默认已是当前月时即停留当前月；当默认是上月时，可切到本月）。不要求支持任意历史月（实现可先只允许：默认月 ∪ 当前月）。

## 6. 数据模型

### 6.1 `monthly_reviews`

| 字段 | 说明 |
|------|------|
| `id` | UUID PK |
| `employee_id` | FK → employees |
| `year`, `month` | 核审年月 |
| `confirmed_at` | 员工确认时间 |
| 唯一约束 | `(employee_id, year, month)` |

存在即表示该员工该月已核审并锁定。

### 6.2 `time_disputes`

| 字段 | 说明 |
|------|------|
| `id` | UUID PK |
| `employee_id` | FK |
| `work_date` | 异议日 |
| `year`, `month` | 冗余便于列表筛选 |
| `entry_id` | 提交时关联的原条目，可空（未安排） |
| `original_status` | 快照：`on_duty`/`rest`/`leave`/`support`/`unassigned` |
| `original_start_time` / `original_end_time` | 可空 |
| `original_ot_start_time` / `original_ot_end_time` | 可空 |
| `proposed_start_time` / `proposed_end_time` | 建议主时段 |
| `proposed_ot_start_time` / `proposed_ot_end_time` | 建议加班；两端皆空 = 清除加班 |
| `note` | 可选 |
| `status` | `pending` \| `confirmed` \| `rejected` |
| `resolved_at` | 处理时间，可空 |
| `resolved_entry_id` | 确认后落地的 entry，可空 |

约束：`(employee_id, work_date)` **唯一**（月锁定后同一天只会有一条异议历史）。审核始终针对单行 `id`。

## 7. API（示意）

| 用途 | 方法与路径 |
|------|------------|
| 员工月明细（含是否已核审、已有异议） | `GET /api/reviews/employee-month?name=&year=&month=` |
| 提交核审 + 异议列表 | `POST /api/reviews/submit` |
| 管理端异议列表 | `GET /api/reviews/disputes?status=&year=&month=` |
| 单条确认 | `POST /api/reviews/disputes/{id}/confirm` |
| 单条无效 | `POST /api/reviews/disputes/{id}/reject` |

### 7.1 提交体要点

- `name`, `year`, `month`
- `disputes[]`：每项含 `work_date`、建议主时段、建议加班、`note?`
- 事务：月核审记录 + 全部异议同行提交；已锁定则 409/业务错误

### 7.2 确认落库规则（单日）

1. 建议主时段必须成对且结束晚于开始。
2. 加班：成对且合法，或双空（清除）。
3. 若存在原 `WorkEntry`：更新为 `status=on_duty`，写入建议主时段/加班。
4. 若不存在：新建 `on_duty` 条目。
5. 仅处理该 `dispute.id`；其他天异议状态不变。

## 8. 前端

### 8.1 导航（`AppShell`）

- **工时核审** → `/review`
- **异议审核** → `/review/admin`
- 保留：工作日历、统计看板

### 8.2 员工页

- 姓名门闩 → 月视图列表 → 行内异议表单 → 底部确认（二次确认文案：提交后不可再改）
- 已锁定月：只读 + 异议状态展示

### 8.3 管理页

- 筛选待审/已确认/无效
- 每条独立「确认」「无效」按钮

## 9. 校验与错误

| 场景 | 行为 |
|------|------|
| 姓名不在花名册 | 明确错误，不进入 |
| 月已核审再提交 | 拒绝 |
| 主时段不成对 / 结束不晚于开始 | 拒绝该次提交或该条确认 |
| 加班只填一端 | 拒绝 |
| 对非 pending 再确认/无效 | 拒绝 |
| 确认落库失败 | 异议保持 pending，返回错误 |

## 10. 测试要点

- 提交后月锁定；再次提交失败。
- 无异议提交：仅有 `monthly_reviews`，无 `time_disputes`。
- 确认：已有到岗更新时段；未安排新建到岗；加班可新增与清空。
- 确认 A 天不影响 B 天 pending。
- 无效不改变 `WorkEntry`。
- 姓名不存在、时段非法有明确错误。
