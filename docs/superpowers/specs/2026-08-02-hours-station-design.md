# 工时工作站（Hours Station）设计规格

**日期：** 2026-08-02  
**状态：** 已实现（as-built，随代码同步）  
**范围：** 网页端工时登记与月度统计（无登录）  
**代码位置：** `.worktrees/hours-station/`（实现主目录）

---

## 1. 产品目标

提供一个打开即用的工时工作站：按日登记员工工作安排，按月查看与统计。面向管理者日常录入与汇总查看，交互简洁、信息清晰。

### 1.1 本版范围（In）

- 工作日历页：月历 + 日明细，支持增删改、清空当日
- 统计看板页：月度总览、按人汇总、逐日明细（含休息）
- 员工花名册：自由输入姓名；不存在则登记时自动加入；可软删除移出花名册
- 整日复制到指定日期；单人安排快速复制（可改姓名 / 时段 / 备注）
- 当日预览弹窗：格式化文本 + 一键复制到剪贴板（便于微信粘贴）
- 人数 / 工时 / 天数等量化数字统一视觉强调（Metric）
- React 前端 + FastAPI 后端 + PostgreSQL

### 1.2 本版不做（Out）

- 登录 / 权限 / 多租户
- 跨夜班（结束时间早于开始时间）
- 手动覆盖最终工时、可配置休息扣除时长
- 导出报表、审批流

## 4. 功能规格

### 4.1 工时算法

对每条排班记录：

1. `raw_hours = end_time - start_time`（同一自然日，要求 `end_time > start_time`）
2. 若 `raw_hours >= 6`：`effective_hours = raw_hours - 0.5`
3. 否则：`effective_hours = raw_hours`
4. 展示与统计一律使用 `effective_hours`，保留 1 位小数

计算在**服务端**完成，前端只展示结果，避免前后端不一致。

### 4.2 员工花名册

- 登记时使用姓名组合框：可搜索已有员工，也可自由输入姓名
- 姓名不在花名册时：**不弹确认框**，提交时默认自动加入花名册
- 姓名在花名册内唯一（存储前 trim；比较为 trim 后精确匹配；最长 64）
- 下拉项可点 × **软删除**（`is_active = false`）：列表不再显示，历史排班保留；再次输入同名会重新激活
- 打开姓名下拉且传入当前月历年月时：每人额外展示 **当月已排工时**（`month_hours`）

### 4.3 工作日历

#### 布局

- 左约 2/3：月历
- 右约 1/3：选中日明细
- **硬约束：** 左侧月历整月（最多 6 行）在主内容区一屏完整展示，**禁止纵向滚动**；日期格在可用区域内尽量接近正方形，随视口缩放
- 右侧人员列表过长时，**仅右侧可滚动**

#### 月历

- 可切换上/下月
- 默认选中今天；若浏览非本月，默认选中该月 1 日
- 日期格展示：
  - 无数据：仅日期
  - 有数据：**始终**展示「人数 · 合计工时」（不依赖是否选中）；选中日额外高亮边框/底色
- 月标题附近显示本月已登记天数与合计工时（Metric 强调）

#### 日明细

- 顶部：选中日期、当日人数与合计有效工时（Metric）、操作按钮
- 操作：`预览`｜`复制到…`｜`清空当日`｜`新增`
- 人员列表每行：姓名（左）| 时段（居中）| 有效工时（右，Metric）|「复制 / 编辑 / 删除」；备注单独下一行（过长换行）
- **新增表单**与**单人复制草稿**固定出现在列表**最上方**；打开时右侧滚动区回到顶部，避免数据多时需下滑填写
- 支持新增、编辑、删除；**同日同人不可重复**；冲突时明确提示并阻止提交

#### 时间输入

- 自定义时/分弹层（非浏览器原生 `input[type=time]` 弹层，因其无法可靠定制）
- 分钟选项以 `00` / `30` 为主；若历史数据存在其它分钟，编辑时临时保留该选项
- 默认时段示例：开始 `07:30`，结束 `16:00`

#### 当日预览

1. 点击「预览」打开弹窗
2. 标题区展示：日期 · 合计工时
3. 正文按人列出安排；长备注自动换行
4. 文本格式（对齐用半角空格补齐；姓名后中文冒号）：

```text
2026年8月2日  合计 32.5h
张三：  7:30-16:00   8h  (开门)
李四：  8:30-16:00  7.5h  (制机位)
```

5. 「复制」写入剪贴板：第一行为日期与合计工时，其后为人员明细，便于微信粘贴

#### 清空当日

- 「清空当日」确认后删除该日全部排班（`DELETE /api/entries?date=`）
- 历史花名册不受影响

#### 复制 — 整日（交互方案 A）

1. 在某日明细点击「复制到…」
2. 进入粘贴模式：顶栏显示粘贴条（来源日、条数、取消）
3. 在月历上点击目标日完成粘贴
4. 目标日已存在同名员工的条目：**跳过**该条，结束后汇总提示跳过数量
5. 时段、备注随记录复制；工时按规则重算（与源一致）

#### 复制 — 单人

1. 点击某人行的「复制」
2. 在列表**顶部**插入高亮草稿行：姓名待填；时段 / 备注可改（预填来源）
3. 确认「完成」后，以当前表单内容 `POST /api/entries` 写入**当前选中日**（非仅改姓名的专用复制接口路径为主交互）
4. 同日重名则阻止；新姓名自动入花名册

### 4.4 统计看板

#### 结构

- 月份切换（上月 / 下月）
- 顶部摘要（三项，Metric）：当月总工时、登记人数、出勤人天
- 主体：按人汇总表，默认按总工时降序；出勤 / 休息 / 工时等数字使用 Metric 强调

#### 汇总列表列

| 列 | 含义 |
|----|------|
| 姓名 | 员工姓名 |
| 出勤天数 | 当月有排班记录的天数 |
| 休息天数 | 当月天数 − 出勤天数 |
| 总工时 | 当月有效工时合计 |
| 日均工时 | 总工时 ÷ 出勤天数（出勤为 0 时显示 —） |

仅统计在当月**至少有一条排班**的员工（登记人数）；其休息天数按当月自然日补齐计算。

#### 行展开（必须）

点击某人一行，展开「当月每日明细」，**覆盖该月每一天**（1…月末）：

| 日期 | 时段 / 状态 | 当日工时 |
|------|-------------|---------|
| 有排班 | `HH:mm – HH:mm` | 有效工时 |
| 无排班 | **休息** | — |

## 5. 视觉与交互原则

- 方向：**墨绿纸感** — 暖灰绿纸感背景、墨绿强调、深墨色标题；避免通用紫渐变与厚重卡片堆叠
- **量化数字（Metric）：** 人数 / 工时 / 天数使用衬线数字 + 墨绿强调色 + 浅绿 chip 底，与正文明显区分；单位（人 / h / 天）略小
- 日历格疏朗，信息密度克制；有数据日期格默认展示人数与工时
- 复制优先「日历点选 + 行内草稿」，少用打断式弹窗；预览/清空等用轻量确认或弹层
- 动效克制：选中日、粘贴模式、展开行可用轻量过渡

## 6. 技术架构

```
[浏览器 React SPA]  --REST/JSON-->  [FastAPI]  --SQL-->  [PostgreSQL]
```

### 6.1 前端

- Vite + React + React Router：`/`、`/stats`
- 关键：页面级请求与本地 UI 状态（选中日、粘贴模式、展开行、预览弹窗）
- 代理：`vite.config.js` 将 `/api` 转到 `VITE_API_PROXY` 或默认 `http://127.0.0.1:8000`
- 关键组件（节选）：`MonthCalendar`、`DayPanel`、`EntryForm`、`EmployeeNameField`、`TimeField`、`DayPreviewModal`、`Metric`、`PasteModeBar`

### 6.2 后端

- FastAPI，REST API
- 工时计算、唯一性校验、复制事务、清空当日在服务端完成
- CORS 配置允许前端开发源与部署源
- 迁移：Alembic（含 `employees.is_active` 等）

### 6.3 数据模型

#### `employees`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| name | VARCHAR(64) | 唯一，trim 后存储 |
| is_active | BOOLEAN | 花名册是否显示；软删除为 false |
| created_at | TIMESTAMPTZ | |

#### `work_entries`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| work_date | DATE | 工作日 |
| employee_id | FK → employees | |
| start_time | TIME | |
| end_time | TIME | 必须晚于 start_time |
| note | TEXT | 可空 |
| created_at | TIMESTAMPTZ | |
| updated_at | TIMESTAMPTZ | |

约束：`UNIQUE (work_date, employee_id)`

> 有效工时不落库；查询时由服务端计算后返回。

### 6.4 API 一览（逻辑）

**员工**

- `GET /api/employees?q=&year=&month=` — 活跃花名册；`year`+`month` 同时提供时附带 `month_hours`
- `DELETE /api/employees/{id}` — 软删除（移出花名册，204）
- 创建可内嵌于排班创建（按名 get-or-create；若曾软删除则重新激活）

**日历与排班**

- `GET /api/calendar?year=&month=` — 每日：entry_count、total_effective_hours；另含 registered_days、month_total_hours
- `GET /api/entries?date=YYYY-MM-DD` — 当日明细（含 employee_name、effective_hours）
- `POST /api/entries` — 新增（姓名 get-or-create；同日重名 409）
- `PATCH /api/entries/{id}` — 更新
- `DELETE /api/entries/{id}` — 删除单条
- `DELETE /api/entries?date=YYYY-MM-DD` — 清空当日全部

**复制**

- `POST /api/entries/copy-day` — body: `{ from_date, to_date }` → 返回 copied / skipped
- `POST /api/entries/copy-person` — body: `{ source_entry_id, name, date }` → 写入指定日（API 仍保留；前端单人复制主路径可为新建条目）

**统计**

- `GET /api/stats/monthly?year=&month=` — 总工时、登记人数、出勤人天、按人汇总（含休息天数、日均）
- `GET /api/stats/monthly/{employee_id}/days?year=&month=` — 该月逐日（工作或休息）

错误响应使用明确中文或稳定 error code，便于前端提示。

## 7. 错误与边界

| 场景 | 行为 |
|------|------|
| 结束时间 ≤ 开始时间 | 拒绝，提示时段无效 |
| 同日同人重复 | 拒绝（409），提示已存在 |
| 整日复制遇重名 | 跳过该条，返回跳过列表/数量 |
| 单人复制 / 新增遇重名 | 拒绝当前操作 |
| 空日复制 | 提示当日无安排可复制 |
| 清空当日 | 需确认；删除该日全部条目 |
| 花名册软删除 | 下拉不再显示；历史条目保留；同名再录可复活 |
| 统计展开未来月份日期 | 仍按自然月列出；无排班即休息 |

## 8. 测试要点

- 工时：5.5h 不扣；6.0h → 5.5h；8.5h 原始 → 8.0h 有效等边界
- 同日同人唯一约束
- 新姓名自动入花名册；软删除与再激活
- 员工列表带 `year`/`month` 时返回 `month_hours`
- 整日复制跳过逻辑；单人复制可改时段/备注后写入
- 清空当日
- 统计：休息天数 = 当月天数 − 出勤；逐日列表长度 = 当月天数
- 月历在常见桌面分辨率下一屏完整可见；有数据格默认显示人数与工时
- 预览文案首行含日期与合计；复制到剪贴板可用
