# 排班文本快速导入 + 加班段 + 整日备注

日期：2026-08-18  
状态：已确认（brainstorming）  
范围：日详情粘贴多日排班文本 → 预览纠错 → 批量写入；原生支持可选加班时段；新增整日备注  
相关代码：`backend/app/services/entries.py`、`backend/app/services/hours.py`、`backend/app/models.py`、`frontend/src/components/DayPanel.jsx`、`EntryForm.jsx`、`SupportForm.jsx`

---

## 1. 背景

门店排班常以微信/备忘录文本下发，格式大致为：

- 日期行：`8月1   周六   团餐47`
- 到岗行：`8-16梓野（早值、检查效期）7.5`，或改班 `8.5-19苑菱…10（10-23.5）`
- 状态行：`休息：苑菱` / `请假：洁惠` / `支援上社：洁怡` / `支援：洁慧 12-21`
- 加班行：同日另起 `继鹏22-23.5`（主状态可为休息或到岗）
- 汇总行：`总：72.5+（试工）4`（仅供人读，系统忽略）

现有系统每人每日一条 `work_entry`，工时由时段按规则重算；支援必须有时段；无整日备注；无第二段工时。管理者需要一次粘贴多天文本并快速落库，且个人工时以系统计算为准（忽略文本末尾小时数）。

## 2. 目标

1. 日详情顶部支持**文本导入**：粘贴 → 解析预览 → 确认写入（可一次多天）。
2. 自动识别到岗 / 休息 / 请假 / 支援 / 试工 / 改班 / 加班 / 整日备注。
3. 原生支持**可选加班段**（`ot_start_time` / `ot_end_time`）；有效工时 = 主时段有效工时 + 加班段有效工时（各段分别套用现有扣减规则后相加）。
4. 新增**整日备注**（按 `work_date` 唯一），承接日期行说明。
5. 同人同日已有登记则**覆盖**；文本未提及的人**保留**；不在花名册的姓名**自动建档**。

## 3. 非目标

- Excel / 图片 OCR 导入
- 模糊姓名对齐（「潔惠」≈「洁惠」）或谐音纠错
- 校验或写入文本中的「总：xx」小时数
- 取消「每人每日一条」主记录约束（加班挂在同一条上，不拆成多行）
- 改统计看板的休息天数口径（仍按既有规则；仅工时数字纳入加班段）

## 4. 已确认决策

| 项 | 选择 |
|----|------|
| 架构 | 方案 1：后端 preview + commit 两步 API |
| 同人同日已有 | 覆盖整行（状态、主时段、加班段、备注、试工） |
| 未出现在文本中的人 | 保留不动 |
| 无时段支援 | 预览标红，补时段后才可提交 |
| 日期行说明 | 写入整日备注 |
| 缺少年份 | 年 = 当前日历视图的年；月日 = 文本 |
| 第二段工时 | 主记录 + 可选加班段（方案 C） |
| 改班 vs 加班 | 行末括号时段 → 改主时段；**行首姓名+时段** → 加班段（非主时段） |
| 入口 | 日详情顶部 |
| 新人 | `get_or_create` 自动建档 |
| 文本小时数 | 忽略，以系统重算为准 |

## 5. 数据模型

### 5.1 `work_entries` 加班段

新增可空列：

- `ot_start_time: TIME NULL`
- `ot_end_time: TIME NULL`

约束（服务层，与现有一致风格）：

- 二者同空或同有；若有则 `ot_end > ot_start`。
- `rest` / `leave`：主时段仍必须为空；**允许**仅有加班段（休息日晚间加班）。
- `on_duty` / `support`：主时段规则不变；加班段可选。
- `support` / `rest` / `leave`：仍禁止 `is_external` / `is_trial`（与现逻辑一致）；试工仅 `on_duty`。

### 5.2 有效工时

```
hours(entry) =
  (主时段有效工时，若有主 start/end) +
  (加班段有效工时，若有 ot_start/ot_end)
```

每段独立调用现有 `effective_hours(start, end)`（各自套扣减档），再相加并格式化为一位小数。  
`rest`/`leave` 无主时段时，仅加班段贡献工时。  
日历日合计、员工月合计、统计看板到岗/支援工时均走同一公式。

### 5.3 `day_notes`

新表（推荐独立表，避免污染 entry）：

| 列 | 类型 | 说明 |
|----|------|------|
| id | UUID PK | |
| work_date | DATE UNIQUE | 自然日 |
| note | TEXT | 非空 trim 后保存；空串则删除行 |
| created_at / updated_at | DateTime | |

导入时：日期行除「N月D / 星期」外的说明写入/覆盖该日 `note`。  
日详情可读可改；无备注则不展示或显示占位。

## 6. 解析规则

输入：`text` + `year`（来自日历当前年）。月份、日来自文本日期行。

### 6.1 日期行

匹配（示例）：`^\s*(\d{1,2})\s*月\s*(\d{1,2})` 或等价 `M-D`。  
开启新日 `date(year, M, D)`。非法月日 → 该块错误。  
同行去掉星期词（周[一二三四五六日天]、星期…）后剩余 trim 文本 → **整日备注**（可空）。

### 6.2 到岗行

模式直觉：`起-止` + `姓名` + 可选 `（备注）` + 可选尾随小时数 + 可选 `（改班起-止）`。

- 时间 token：整数或一位小数 → `H` 或 `H.5` → `HH:00` / `HH:30`（如 `23.5`→23:30，`7.5`→07:30，`14.5`→14:30）。
- 姓名：时段后至 `（` 或行末数字前的汉字/字母片段；需能识别常见 2–3 字名。
- 括号备注：保留原文（顿号分隔）；若含「试工」→ `is_trial=true`，备注仍保留全文（或去掉「试工」二字——**实现取保留全文，试工靠 flag**）。
- 尾随单独数字（如 `7.5`、`10`）**丢弃**。
- 若再出现括号时段 `（10-23.5）` → **改班**：主 `start/end` 替换为该时段。
- 默认 `status=on_duty`。

示例：

| 原文 | 结果 |
|------|------|
| `16-23.5嘉岚（卫生）6.5` | 嘉岚，16:00–23:30，note=卫生，非试工 |
| `8-13林航（试工水果位）5` | 林航，08:00–13:00，note=试工水果位，is_trial |
| `8.5-19苑菱（早值、检查效期）10（10-23.5）` | 苑菱，10:00–23:30，note=早值、检查效期 |

### 6.3 休息 / 请假

- `休息：A B C` / `休息:A、B`（冒号中英文；分隔空白/顿号/逗号）→ 每人 `status=rest`，无主时段、无试工。
- `请假：…` → `status=leave`，同上。

### 6.4 支援

- `支援上社：洁怡` → `status=support`，`note=上社`，**无时段 → 预览 error，须补**。
- `支援：洁慧 12-21` → support + 12:00–21:00；前缀「支援」后若有地点词可进 note。
- `支援上社：洁怡 12-21` → support + 时段 + note=上社。

### 6.5 加班行

**判定**：行**以姓名开头**（非 `起-止` 开头），后接 `起-止`（如 `继鹏22-23.5`）→ 只写入该人 **加班段** `ot_*`，**不**把该时段当作主到岗时段，也**不**因该行单独改写 `status`。

合并：

- 若该人本日尚无草稿，先建草稿（主时段空、`status` 暂缺省为 `on_duty`，可被后续休息/请假/到岗行覆盖）。
- 典型：`继鹏22-23.5` + 其后 `休息：…继鹏` → 最终 `rest` + `ot 22:00–23:30`。
- 若已有到岗主时段，加班行只补/覆盖 `ot_*`。

与到岗/状态行冲突合并顺序：**按文本出现顺序**；后写覆盖先写同名字段（最终一人一日一条草稿）。

### 6.6 忽略

- 空行
- `总：…` / `总:…`（含全角加号等变体）
- 无法归类的行 → 进入预览 `unparsed` / 标红，默认不提交

## 7. API

### 7.1 预览

`POST /api/entries/import/preview`

```json
{ "text": "...", "year": 2026 }
```

响应（示意）：

```json
{
  "days": [
    {
      "work_date": "2026-08-01",
      "day_note": "完成5号前自检表+QSE自检表",
      "entries": [
        {
          "name": "嘉岚",
          "status": "on_duty",
          "start_time": "16:00",
          "end_time": "23:30",
          "ot_start_time": null,
          "ot_end_time": null,
          "is_trial": false,
          "note": "卫生",
          "errors": []
        }
      ],
      "errors": []
    }
  ],
  "unparsed_lines": []
}
```

条目级 `errors` 例：`missing_support_times`、`invalid_time_range`。  
有任意阻断错误时，前端禁用确认；用户可在预览改字段后，**以编辑后的草稿提交 commit**（不必再 parse）。

### 7.2 提交

`POST /api/entries/import/commit`

```json
{
  "days": [
    {
      "work_date": "2026-08-01",
      "day_note": "...",
      "entries": [ { "name", "status", "start_time", "end_time", "ot_start_time", "ot_end_time", "is_trial", "note" } ]
    }
  ]
}
```

行为：

1. 整请求**单一事务**。
2. 每人：`get_or_create_employee` → 若该日已有 entry 则更新覆盖，否则创建。
3. 未出现在 payload 的当日其他人不动。
4. `day_note`：非空 upsert；空/null 可表示不改或清空——**约定：字段缺省=不改；显式 `""`=删除整日备注**。
5. 任一条规范化失败 → 回滚，400 + 明细。

响应：`{ "created": n, "updated": m, "day_notes_upserted": k }`。

### 7.3 整日备注 CRUD

- `GET /api/day-notes?date=YYYY-MM-DD` 或并入日 entries 列表响应旁路字段 `day_note`
- `PUT /api/day-notes/{date}` `{ "note": "..." }`

推荐：日 entries 的 list API 增加可选 `day_note`，减少一轮请求；另保留 PUT 供面板内联编辑。

### 7.4 Entry schema 扩展

`EntryCreate` / `EntryUpdate` / `EntryOut` 增加 `ot_start_time` / `ot_end_time`；`EntryOut.effective_hours` 含加班段。  
复制整日 / 单人复制：加班段一并复制。

## 8. 界面

1. **日详情顶部**：「文本导入」按钮 → 弹层大文本框 →「解析预览」。
2. **预览**：按日分组；整日备注可编辑；每人一行可改状态/主时段/加班段/试工/备注；错误行标红；全部阻断错误清除后启用「确认导入」。
3. **成功**：关闭弹层，刷新日历点与日列表。
4. **日常表单**：`EntryForm` / `SupportForm` / 休息请假表单增加可选加班段时间框；列表行展示主时段，有加班时附注加班时段；工时数字为合计。
5. **整日备注**：日详情标题区展示与编辑。

## 9. 边界行为

| 场景 | 行为 |
|------|------|
| 文本写 8 月、日历年 2026 | → 2026-08-* |
| 同日文本有苑菱、系统另有张三 | 覆盖/写入苑菱；张三保留 |
| `支援上社：洁怡` 无时段 | 预览 error，补时段后可提交 |
| `继鹏` 在休息且 `继鹏22-23.5` | rest + ot 22:00–23:30 |
| `…10（10-23.5）` | 主时段改为 10:00–23:30 |
| 新人名 | 自动建档 |
| `总：72.5` | 忽略 |
| 结束≤开始 | 条目 error |
| commit 中一条非法 | 整批回滚 |
