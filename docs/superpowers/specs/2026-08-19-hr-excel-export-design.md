# 人事工时 Excel 导出

日期：2026-08-19  
状态：已确认（brainstorming）  
范围：统计看板按月导出人事排班表；花名册维护导出姓名、岗位、拖动顺序；设置维护店名  
相关代码：`backend/app/models.py`、`backend/app/services/employees.py`、`backend/app/services/stats.py`、`frontend/src/pages/StatsPage.jsx`、`frontend/src/components/RosterSettingsPanel.jsx`、`frontend/src/components/SettingsModal.jsx`  
模板来源：`f:\RecordTmp\东圃地铁站店7月份.xls`（实现时转为 `.xlsx` 纳入仓库）

---

## 1. 背景

人事用一份固定样式的月度表（店名、日期、星期、每人两行「上班/下班」、能力=岗位、右侧總計/总工时/三薪/支援/Rate）。系统里已有每日到岗/休息/请假/支援与「没吃饭」标记，但没有按该表格式导出，也没有岗位、导出全名和花名册顺序。

## 2. 目标

1. 统计看板当前查看月可下载人事 Excel，**样式与模板一致**。
2. 表头日期与星期与该月公历一致。
3. 只导出**当月有任意登记**的人员；无登记者不出现。
4. 花名册可维护**岗位**、**导出姓名**，并可**拖动排序**；导出按该顺序。
5. 每日上班/下班按约定把系统时段换成小时小数（见 §6）。

## 3. 非目标

- 从 Excel 再导入回系统
- 独立岗位字典 / 岗位排序表（岗位为每人自由文本）
- 改日常登记短名；改统计看板数字口径
- 计算或改写總計 / 总工时 / 三薪 / Rate（保留模板原有公式或空值）
- 继续输出旧 `.xls`（导出为 `.xlsx`）

## 4. 已确认决策

| 项 | 选择 |
|---|---|
| 文件生成 | 方案 1：仓库内 `.xlsx` 模板 + openpyxl 填数下载 |
| 入口 | 统计看板当月标题旁「导出 Excel」 |
| 导出姓名 | 花名册单独字段；空则用日常短名 |
| 谁进表 | 当月有任意 `work_entries`（到岗/休息/请假/支援） |
| 休息/请假无加班 | 该日上下班空 |
| 休息/请假仅加班 | 按加班起止填，不加 0.5 |

| 岗位与顺序 | 每人岗位自由文本 + 花名册拖动顺序 |
| 右侧合计 | 不改公式/样式；系统只写每日格与支援列 |
| 不足 31 天 | 多出的日期列留空（无日期、无星期），格子样式保留 |
| 店名 | 设置项，默认「东圃地铁站」，写入表头 |

## 5. 数据模型

### 5.1 `employees`

| 列 | 类型 | 说明 |
|---|---|---|
| `export_name` | `VARCHAR(64) NULL` | 导出用全名；空则用 `name` |
| `position` | `VARCHAR(64) NULL` | 岗位，对应表「能力」 |
| `sort_order` | `INTEGER NOT NULL DEFAULT 0` | 花名册与导出顺序；越小越靠前 |

日常登记、导入人名仍用 `name`，不改唯一约束。

### 5.2 店名

设置增加 `store_name`（单行配置即可），默认 `东圃地铁站`。导出文件名：`{store_name}店{月}月份.xlsx`（月为阿拉伯数字，如 `7`）。

## 6. 上下班换算

时间 → 小时小数：`HH:MM` → `H + M/60`（`:30` → `.5`）。写入单元格用数字（一位小数，整点可写整数）。

记 `start_h` / `end_h` 为主时段，`ot_hours` 为加班段时长（有完整加班起止才算，否则 0）。

### 6.1 到岗、支援（有主时段）

| 没吃饭 | 上班 | 下班 |
|---|---|---|
| 未勾 | `start_h + 0.5` | `end_h + ot_hours` |
| 已勾 | `start_h` | `end_h + ot_hours` |

例：`07:30–16:00` 未勾没吃饭 → 上班 `8`、下班 `16`；加班 1.5h → 下班 `17.5`。已勾没吃饭 → 上班 `7.5`、下班 `16`（加班同样加在下班上）。

无主时段的到岗/支援：该日上下班空（与入职前空格相同）。

### 6.2 休息、请假

- 无加班：上下班空。
- 仅有完整加班段：上班 = 加班开始小时，下班 = 加班结束小时，**不加 0.5**。

### 6.3 支援列

该人当月所有 `status=support` 记录的有效工时之和（与系统 `effective_hours` 同一公式）。无支援则空或 0（以实现时与模板空值习惯一致：无支援留空）。

### 6.4 入职前 / 无记录日

该日上下班空。不补「未出勤」标记。

## 7. 模板填写

实现时将样例 `.xls` 转为 `.xlsx`，放入例如 `backend/app/templates/hours_export.xlsx`。导出时**复制工作簿**再写值，不改边框、字号、合并、列宽、行高、填充色；不改總計/总工时/三薪/Rate 单元格公式。

表结构（与样例一致）：

- 第 1 行：店名、月份锚点日期、1–31 日、總計
- 第 2 行：「能力」、星期行
- 每人两行：序号、姓名、岗位、上班行；下一行下班
- 日列：第 `3+day` 列对应公历日（1 日在样例第 4 列）

填写：

1. 店名、当月 1 日（Excel 日期）
2. 日 `1..days_in_month` 写日期数字与「周×」；超出天数的列清空日期与星期，保留样式
3. 按 `sort_order`、`created_at` 列出当月有登记的人；序号从 1 起
4. 姓名用 `export_name` 或 `name`；能力用 `position`（可空）
5. 各日上下班按 §6；支援列按 §6.3
6. 模板里多出来的空白人员槽：清空姓名/岗位/日值，保留「上班/下班」行结构，以免破坏公式引用

人员多于模板槽位时：按模板行样式**追加**成对的上班/下班行（复制上一对的样式），再填数。

## 8. API 与界面

| 接口 | 作用 |
|---|---|
| `PATCH /api/employees/{id}` | 更新 `export_name`、`position`（trim；超长 400） |
| `PUT /api/employees/reorder` | `{ ids: UUID[] }` 按数组重写 `sort_order` |
| 设置读写 | 含 `store_name` |
| `GET /api/stats/monthly/export?year=&month=` | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` 附件下载 |

列表员工接口返回新字段，花名册按 `sort_order` 排序。

界面：

- 设置 → 花名册：每人岗位、导出姓名；列表拖动排序（松手即保存）
- 设置：店名
- 统计看板：「导出 Excel」按当前年月下载；失败用现有错误条。当月无人登记时仍可下载（仅表头与空人员槽）

## 9. 测试

- 换算：`7:30–16:00` 未勾没吃饭 → `8 / 16`；勾了 → `7.5 / 16`；加班 1.5h → 下班 +1.5
- 休息+加班只填加班起止；纯休息空
- 支援日填上下班，支援列等于该月支援有效工时
- 2026-02 表头星期与日历一致，29–31 列无日期无星期
- 导出顺序 = 花名册 `sort_order`；当月无登记者不出现
- 导出 HTTP 200、文件名含店名与月份；打开后日列与样例列对齐

## 10. 实现要点

- 依赖：`openpyxl`（只写 `.xlsx`）
- 纯函数：`time_to_hour_number`、`clock_in_out_for_entry(entry) -> (in, out) | (None, None)`，便于单测
- 导出服务读当月全部 `work_entries`（含员工），再填模板
