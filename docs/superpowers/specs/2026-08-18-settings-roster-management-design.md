# 设置：花名册管理

日期：2026-08-18  
状态：已确认（brainstorming）  
范围：设置弹窗新增「花名册」分区；文本导入与单人添加；删除沿用现有软删  
相关代码：`frontend/src/components/SettingsModal.jsx`、`backend/app/services/employees.py`、`backend/app/routers/employees.py`

---

## 1. 背景

花名册目前只能在登记时自由输入、或在姓名下拉里点 × 软删。开店初期或人员变动时，管理者需要一次性粘贴名单、在设置里集中维护，而不必逐条登记工时。

软删语义已经存在：`employees.is_active = false`，历史 `work_entries` 保留；同名再录入会重新激活。

## 2. 目标

1. 设置弹窗新增 **花名册** 分区（方案 1）。
2. 支持 **单人添加**、**文本导入**、**移出（软删）**。
3. 导入分隔符：空格、换行、制表符、顿号 `、`、英文逗号 `,`、中文逗号 `，`、分号 `;`/`；`。
4. 已在册活跃人员跳过；已软删同名复活（口径 A）。

## 3. 非目标

- 独立路由 `/roster`
- 改名、查看已移出人员、导出、Excel 上传
- 导入前预览确认
- 硬删除员工或历史排班
- 改统计看板或排班占用规则

## 4. 已确认决策

| 项 | 选择 |
|----|------|
| 入口 | 设置弹窗左侧导航新分区「花名册」 |
| 能力 | 列表 + 单人添加 + 文本导入 + 移出 |
| 导入重复 | 活跃跳过；软删同名复活 |
| 分隔符 | 空白（含换行/制表符）、`、`、`,` |

## 5. 界面规格

设置导航顺序：备注预设 → **花名册** → 工时计算。

分区内容：

1. **标题行**：「花名册」+ 右上角 **添加 / 导入** 按钮（始终可见，不跟列表一起滚出视野）。
2. 短提示：移出后下拉不再显示，历史工时保留。
3. **人员列表**：`GET /api/employees` 的活跃人员，按姓名排序；每行姓名 +「移出」。
4. 点击「添加 / 导入」打开二次弹窗：一个文本框可输入单人或粘贴多名（空格、换行、顿号、中英文逗号、分号）；确定后走 `POST /api/employees/import`。Esc / 取消只关该弹窗，不关设置。

删除确认文案与姓名下拉一致：

> 将「{name}」移出花名册？  
> 下拉列表中不再显示；已登记的历史工时会保留。

导入成功后清空文本框，只展示非零项，例如 `新增 2`；有复活/跳过/无效时才追加。单人已在册提示「已在册」。

单人添加已在册活跃人员：提示已在册，不报失败。

## 6. 数据与 API

沿用 `employees` 表。列表、删除不改语义。

| 操作 | 方法 | 说明 |
|------|------|------|
| 列表 | `GET /api/employees` | 仅活跃；不带年月 |
| 移出 | `DELETE /api/employees/{id}` | `is_active=false`，204 |
| 单人添加 | `POST /api/employees` | `{ "name": "张三" }` |
| 文本导入 | `POST /api/employees/import` | `{ "text": "..." }` |

单人与导入均走现有 `get_or_create_employee`（trim、精确匹配、最长 64、软删复活）。

### 6.1 `POST /api/employees`

- 成功 201：新建或复活；返回 `EmployeeOut`（无 `month_hours` / `month_rest_days`）。
- 已是活跃：200，返回该人，前端提示已在册。
- 空名 / 超长：400。

### 6.2 导入解析（服务端）

1. 用正则把空白（含 `\s`）、`、`、`,` 当作分隔符切开。
2. 各片段 `strip`；空片段丢弃。
3. 同一批按出现顺序去重（精确匹配 trim 后字符串）。
4. 长度不在 1–64：计入 `skipped_invalid`，不写入。
5. 其余对每人 `get_or_create`：
   - 新行 → `created`
   - 原 `is_active=false` → `reactivated`
   - 原已活跃 → `skipped_existing`

响应：

```json
{
  "created": 2,
  "reactivated": 1,
  "skipped_existing": 1,
  "skipped_invalid": 0,
  "names": ["李四", "王五", "赵六"]
}
```

`names` 为本次处理后应出现在活跃花名册中的、本批涉及的姓名（新建+复活+已在册），便于前端刷新列表。空文本（无有效片段）返回 400「没有可导入的姓名」。

### 6.3 前端刷新

设置内改花名册后发出 `roster-changed` 事件（与备注预设事件同模式）。`EmployeeNameField` / `StatusMultiPick` 在打开或已挂载时订阅并重新 `GET /api/employees`。

## 7. 边界行为

| 场景 | 行为 |
|------|------|
| `张三 李四、王五\n赵六,张三` | 四人；张三只处理一次 |
| 导入已有活跃名 | `skipped_existing`，不报错 |
| 导入已移出同名 | 复活，重新出现在列表和下拉 |
| 单人添加已在册 | 200 + 提示已在册 |
| 只有分隔符 / 空文本 | 前端禁用「导入」；若仍提交则 400「没有可导入的姓名」 |
| 移出 | 列表立即少一人；历史排班仍在 |
| 超长姓名 | 导入计入 invalid；单人 400 |
